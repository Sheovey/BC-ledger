# docs/

仓库内的文档镜像。**权威源在项目根目录（`01-Ledger/`），这里的是只读副本。**

| 文件 | 来源 | 说明 |
| --- | --- | --- |
| `项目档案.md` | `../小程序项目档案.md` | 项目事实源：版本演进、页面清单、验收明细、发布流程、工程约定 |
| `助手记忆.md` | `../.workbuddy/memory/MEMORY.md` | 助手的精简长期记忆（每次会话自动注入） |
| `screenshots/` | 界面截图 | README 配图 |

## 为什么要有这一份

根目录的两份文档不在 git 仓库内（仓库根是 `ledger-taro/`），此前**没有任何版本控制与远端备份**。本机磁盘出问题就等于全部丢失。镜像到 `docs/` 后，它们随代码一起进入 GitHub。

## 怎么更新

1. 改**根目录**的源文件（`小程序项目档案.md` / `.workbuddy/memory/MEMORY.md`）。
2. 在 `ledger-taro/` 下执行：

```bash
npm run docs
git add docs && git commit -m "docs: 同步项目档案"
```

脚本会在镜像顶部写入来源路径与生成时间，方便一眼分辨版本新旧。

## 为什么不直接改这里

`npm run docs` 是单向覆盖，改这里会被下次同步冲掉。唯一权威是根目录的源文件。

## 为什么不用符号链接

Windows + git 下软链会被存成 blob，克隆到别的机器可能变成普通文件或直接失败。复制是更可靠的写法，代价是需要记得跑一次同步。
