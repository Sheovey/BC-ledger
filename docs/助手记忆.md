## 版本号与上传

- 三处：`package.json.version`、`settings/index.tsx` 的 `APP_VERSION`、`cli upload -v`。`npm run upload`（`scripts/upload.cjs`）以 package.json 为唯一源，校验不一致即 exit 1；备注自动拼 `<版本> · <日期> · <git 短 sha> · <说明>`。**先 commit 再 upload**，否则 sha 指向上一次提交。
- **备注必须自己加引号**：`wxcli.cjs` 用 `spawnSync(...,{shell:true})`，Node 在 shell 模式下只按空格拼参数、不加引号，带空格的备注被 cmd 拆散（上传成功、只有备注错，不易察觉）。
- **`cli upload` 冷启动会卡死**（停 `initialize`）→ 先 `node scripts/wxcli.cjs islogin` 预热。成功标志：`√ upload` + 体积表 + `EXIT=0`。
- **`cli auto` 的 9420 端口随命令结束释放**，必须串联：`(npm run auto >/dev/null 2>&1 &) ; sleep 24; node scripts/verify-x.cjs`。分开跑必 `ECONNREFUSED`；刚拉起就连会报 `getPageMetaByWebviewId(...) is null`。
- **版本号是自由文本非主键**，风险只在一处：已提审的号继续同名上传 → 后台「审核版本 1.1.x」与「开发版本 1.1.x」内容不同名字相同，极易提错包。

- 三个关卡互不替代：**备案**卡正式访问与搜索、**审核**卡合规、**微信认证**决定「被搜索/被分享」（已认证，2027-10-29 到期）。

## 更新提示（1.1.6 接入，`src/utils/update.ts`）

- 微信在小程序**每次启动（含热启动）**检查更新（官方原文），包下完要**重启小程序**才生效；切后台 30 分钟内回来是热启动，内存里仍是旧代码 —— 这才是「发布后手机上仍显示旧版本」的真因，**不是同步延迟**。**别为刷版本删小程序**，会连账本存储一起清。
- 四条约束：①`applyUpdate()` 会立刻重启 → **必须先 `flushPersist()`**；②`envVersion === 'develop'` 跳过，否则弹窗挡住验收脚本；③基础库 <1.9.90 无此 API，整体 try 兜住；④**记账页与 `sheetDepth>0` 时不弹**，置 pending，靠四个 tab 页的 `useDidShow` 调 `flushPendingUpdatePrompt()` 补弹 —— 因为记账表单全在组件 `useState` 里，只有点保存才进 store，`flushPersist` 救不了正在填的表（这是自动重启真正会丢的东西）。

## 数据与存储

- **storage 是唯一权威源，文件是派生产物**；切账本不读文件。`StorageDriver` = `wx.setStorageSync` + meta/流水分片（**300 条/片**）。
- **备份语义（修过的严重 bug）**：必须**写盘前取旧值**（`previousRaw = lastWrittenRaw` → 写盘 → `rotateBackup(previousRaw)`）。写盘后才备份 → 备份永远等于当前数据、回滚点形同虚设，而界面完全正常。只留 1 份（分片下多份顶到 10MB），超 90 万字符放弃。
- **本机自动存档**：`USER_DATA_PATH/archive/`，每账本 1 个 `.xlsx`（零依赖手写 ZIP + 最小 OOXML，真 Excel 验证过）+ 全局 3 份 JSON。调度：写后 idle 4s、xlsx 最小间隔 60s、`onHide` 只写 JSON、启动后 3s 补一次；`txs.length === 0` 短路不覆盖已有存档。
- **`DATA_VERSION = 2`**：预设改名必须走 `persist.ts` 的 `applyPresetRenames()`（只认「id + 旧名」双命中）。**以后任何预设改名都走这条路**，只改 `seed.ts` 对老数据无效。
- **合规口径**：用户可见文案不得出现 理财/基金/分红/收益/利息/保险/投资/金融/股票/债券/贷款/银行。`cat_finance`/`cat_invest`/图标名 `invest` 是内部标识，保留。
- 首启：1 账本 / 5 账户 / **84 预设分类** / 0 流水。

## 硬规范（别再犯）

- **按下态**：全仓禁 `:hover`/`:active`，一律 `hoverClass` + `--hover`（移动端 `:hover` 松手不解除）。`<Text>` 不支持 `hover-class`，用 `<View>`。
- **选中态**：`accent-soft` 底 + `accent-deep` 字；禁用 `surface-2` 当选中底（与按下态同色）。
- **字号**：正文 ≥13px、辅助 ≥12px；2026-11-06 全站 ≤16px 统一 +1px，主力档 13 / 13.5 / 14.5 / 15.5。**判断「字小」先看对比度**（`--text-3` 仅 2.37:1、`--accent-deep` 2.54:1，均低于 WCAG AA）。
- **共享组件样式必须放全局**：被 ≥2 页使用的类不许定义在页面级 scss（`ConfirmDialog` 曾因此在 6 页错位）。
- **间距别写两遍**：全局 `gap` 与页面级 `margin` 叠成双倍。**`Picker` 是原生组件**，参与 flex 的是 `picker` 而非内部 cell。
- **custom tabBar 两个坑**：①组件树在 `page` 之外，`page{}` 上的 CSS 变量继承不到 → `var()` 参与的声明整条被丢弃（写死 rgb 的还在）；②框架渲染在页面之上，页面内 z-index 无效 → 弹层靠 `useUiStore.sheetDepth` 计数隐藏 tabBar（用计数不用布尔，弹层可嵌套）。
- **自绘光标**：空内容贴最左、有内容贴末尾；点进备注/商家必须收起（`amountActive`），**恢复入口四个**（点金额区 / 按键盘键 / 点「继续输入」 / `switchType`），少一个就是「键盘开着却没有插入点」。按键盘时 `Taro.hideKeyboard()`。**`onFocus` 单独不够，外层 `View` 也要挂 `onClick`**（自动化 tap input 不触发 focus）。
- **自绘状态残留优先查 `sheetDepth`**：泄漏会让 tabBar **永久隐藏且不可自愈**，`verify-sheet` 有开合两条运行态断言。
- **多选分类是「标签」不是「拆分」**：金额只归 `categoryId`（=`categoryIds[0]`，第一个勾的），其余项不参与任何金额统计；一级只能一个，跨根整组替换；模板页仍单选。
- **列表时间戳**由 `TxRow` 的 `stampStyle` 决定：流水页不传（日期在日分组标题）/ 统计 `'date'` / 首页 `'relative'`（今天·昨天·MM-DD，**跨年补年份**）。
- **流水行元信息顺序：账户 · 备注 · 商家**（2026-11-06 老板定）。
- **禁止「点了才说没做」的占位入口**：命中 `暂未接入|未实现|敬请期待|即将上线` 即红。
